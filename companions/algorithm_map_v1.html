La distancia al objetivo, medida. Solo el 22.7% de las ejecuciones resueltas se apoya en la taxonomía propia de SAP. El resto — 2,617,419 ejecuciones sobre 334 entradas curadas a mano — descansa en un mapa que escribimos nosotros y que no viaja. No es un defecto a borrar: los objetos custom no tienen componente SAP por definición, y son justo donde viven los procesos que nos diferencian. El arreglo es derivar ese mapa de lo que cada objeto lee y escribe, para que viaje la derivación aunque no viaje el contenido.

2 · Frente al mercado — qué adoptamos y qué le cambiamos

El motor del campo es pm4py (linaje van der Aalst), el mismo sustrato que Celonis y Signavio productizaron. Reinventar el descubrimiento de DFG sería vanidad; el valor está en lo propio y en las extensiones. La última columna es el modo de fallo — cómo miente cada uno. El mercado no lo publica.

algoritmoorigenestado equivalente de mercadoqué aporta / por qué se extendió modo de fallo
A3_two_axis_classification
explain every call on two independent axes — PROCESS (from the object name) and ORIGIN (from host/destination/user)
 extendido STRONG — process mining assigns activities but does not systematically resolve WHO CALLED. Without origin, a middleware call and an internal report are indistinguishable. an unresolved origin collapses a fleet into one label — 174 middleware endpoints currently read as one caller
B1_dfg_discovery
build the process map from an event log — activities as nodes, observed transitions as edges
 adoptado WORKS pm4py — the reference implementation (van der Aalst lineage), the substrate Celonis and Signavio productised a DFG on the wrong case notion produces a plausible map of a process that does not exist
B2_variant_analysis
group cases by exact path, rank by frequency and cost — the long tail is where exceptions live
 adoptado WORKS — variants computed on a truncated log look like process simplicity
B3_performance_bottleneck
cycle time per transition; waiting versus processing
 adoptado WORKS — timestamps from different systems make a bottleneck out of a clock skew
B4_declarative_conformance
state the normative rules, classify every case against them, quantify the deviation in money
 adoptado STRONG — THIS IS WHERE THE PRODUCT LIVES — the delta between AS-DESIGNED and AS-RUN applying a market normative model without checking the tenant's real shape. A standard O2C model here would report 100% non-conformance because there are ZERO deliveries
B5_ocel2_object_centric
one event references MULTIPLE object types, with no forced single-case notion
 adoptado WORKS — ahead of most commercial tooling. Flat single-case mining forces an artificial case ID and distorts anything convergent or divergent — which public-sector finance is constantly: one budget, choosing object types badly reproduces the single-case distortion in a more expensive format
C3_static_edge_extraction
parse source for reads_tables / calls_fms / writes_tables
 adoptado WEAK — an impact analysis on a thin edge set returns 'nothing depends on this' — the most dangerous possible false negative
D1_D3_delta_strategies
PK-delta for master, value-compare for totals, high-water-mark for transactional
 adoptado STRONG — the intelligence is the ROUTING (table class -> strategy), not the strategies themselves the sync log records domain, table and strategy but NEVER the system — with one golden DB per system that ambiguity is now structural
A1_chunked_temporal_read
read a purging log in bounded time windows (<=6h) because a wide call hangs and the connection degrades every ~12 calls
 propio STRONG ninguno — no existe equivalente comercial a silently truncated window looks like a quiet period in the data
A2_rolling_window_accumulation
capture a window the source purges (7-120 days) into *_history tables, turning a window into a history
 propio FRAGILE NONE — commercial tools connect live and inherit the system's retention a missed day is invisible: the history simply has a hole nobody sees
A4_ordered_classifier_ladder
ordered rule chain (package -> software component -> overlay -> name -> text -> substrate); first match wins, specificity expressed by
propio WORKS ninguno — no existe equivalente comercial ORDER-DEPENDENCE IS SILENT. A greedy early rule steals from a later one and nothing errors. Proven twice in s097: 'FTB' swallowed FTBB (bank statements) into deal managem
A5_adaptive_learning_loop
auto-resolve unknown calls by function group / naming / app domain, LEARN the resolution, re-classify until convergence, expose the remainder as an ex
 propio UNDER_EXERCISED ninguno — no existe equivalente comercial the closest thing the model has to learning — each run explains more with zero hand-coding a learned rule that was wrong once is now wrong permanently and invisibly
A6_frontier_with_substrate_tier
coverage % + explicit worklist, with a third tier for technical substrate (connectivity, session, monitoring): real execution, legitimately non-busine
 propio STRONG ninguno — no existe equivalente comercial substrate becomes a dumping ground if it is ever matched before business rules — it is matched LAST on purpose
C1_component_resolution_chain
object -> TADIR (package) -> TDEVC (component id) -> DF14L (application component)
 propio STRONG ninguno — no existe equivalente comercial the strongest algorithm in the inventory because it is DETERMINISTIC: SAP states the answer instead of us pattern-matching a name. 1.61M objects resolvable. a name-range chunk that returns exactly the cap truncates silently
C1c_custom_fm_domain
custom Z/Y function module -> canonical domain, via the curated tfdir_custom.APP_DOMAIN overlay
 propio WORKS ninguno — no existe equivalente comercial custom FMs have no SAP component by definition, and they are precisely the objects the differentiation rests on. Y_BAPI_WBS_FINANCIAL_DATA_1 (974,868 calls) resolved to nothing until this ru the overlay is CURATED (3,073 FMs). An uncurated custom FM resolves to nothing and looks like a technical object.

D4_field_splitting
split a wide table read into column groups against the 512-byte line buffer, re-join locally

D5_bounded_probe_with_cap_reporting

3 · Anidamiento — la salida de uno es la entrada de otro

Un algoritmo no puede ser mejor que sus dependencias. Mejorar una capa baja levanta todo lo de arriba: el arreglo de L0 llevó la frontera del 40% al 7,7% sin tocar nada superior.

L0_INVARIANT
C1
depende de: nothing but SAP itself
the ground truth every other answer is anchored to. Improving it lifts everything above.
L0b_CUSTOM_OVERLAY
C1c
depende de: the curated APP_DOMAIN overlay
custom Z/Y function modules have NO SAP component by definition — their function group lives in a customer package DF14L cannot resolve. They need their own rung, and they are exactly the objects the product thesis rests on because no commercial tool can label them either.
L1_OBSERVATION
A1 A2 A4 A6
depende de: L0
what runs, when, by whom — classification anchored on the standard

the satellite catalogue
L3_ORIGIN

depende de: L2 (the catalogue), L0/L0b (to resolve what each satellite calls)
a satellite is an ENTITY, not a caller string: identity, channel, volume, direction, the domains it touches
L4_FLOW
B1 B2 B3 B5
depende de: L3 (origin) + the flow model
process mining runs per FLOW, never per module
