Phase 3 — Unit Test D01/V01 (PENDING · June 2026)

Why Phase 3 is "Unit Test" and Phase 4 is "UAT"

Phase 3 is where developers and testers verify V001 produces correct XML — not where business users sign off (that is Phase 4). The distinction matters because the cost of a bug found in Phase 3 is hours; the cost of the same bug found in Phase 4 is days plus stakeholder confidence. Phase 3 catches everything mechanical: schema validation against pain.001.001.03 XSD, BAdI regression on Pattern A, byte-level diff of V000 vs V001 output. Phase 3 fails fast and loud so Phase 4 can focus on judgment calls (does the bank accept this in their test gateway? does Marlies confirm the field mapping matches the source XLS?).

Where Phase 3 runs

Two environments: D01 for the DMEE Test Data path (Phase A V000 testing without activation, plus Phase B V001 testing with the snapshot+activate+test+rollback ritual per DMEE Configuration · the version thing — F8 only tests the Active version, so V001 must be activated locally in D01 to be tested by the SAP engine). Plus V01 for end-to-end F110 runs with V001 activated in V01 (after the Generate Version snapshot of V01's V000) for full-stack BCM/SWIFT integration. Production (P01) stays on V000 throughout Phase 3-4. Bug found = roll back via Version Management Retrieve in the affected D01/V01, fix V001 in D01, re-test. Each test scenario from the matrix in this tab maps to one verifiable XML output.
