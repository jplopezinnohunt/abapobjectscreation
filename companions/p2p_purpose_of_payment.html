The separate note-to-payee mechanism (SWIFT :70)

Y_FI_PAYMEDIUM_NOTE_TO_PAYEE reads YVENDOR_PAYM_REF by (BUKRS, LIFNR, BLART) and writes FPAYP-ZREF01. With no row it falls back to a format chosen by FPAYHX-PREFTYP: 'SAMPLE 01' → No.<xblnr>/<bldat>; 'SAP SEPA' → /INV/<xblnr> <bldat>. Y_FI_PAYMEDIUM_06 and _DMEE_30 read the same table.

Brain correction. The sap_payment_bcm_agent skill states this FM builds EXO//reason//XBLNR// from REGUP-BLART. The string EXO appears in none of the ten recovered sources. That text came from a specification, not from the code. Where EXO// is actually produced is still unknown — likely a DMEE tree constant.

Scope — SocGen only, by written specification

PPC functional spec v2.0 (M. Spronk), page 16: the development is only for the XML file of Société Générale. Citibank payments do not carry PPC. Making a purpose code mandatory for a Citi-routed country is a new development, not a configuration change. (claim 267)
