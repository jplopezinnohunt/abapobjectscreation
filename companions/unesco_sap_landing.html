SAP Data Extraction Compliance — ODP-RFC
SAP Note 3255746 — "Unpermitted usage of ODP Data Replication APIs" (updated 2026-04-13) · Security patch: Patch Day 2026-06-09
✔ Compliant — Not Affected

UNESCO's Gold DB (24M+ rows) is built exclusively with the generic SAP table reader RFC_READ_TABLE. It does not use the ODP Data Replication APIs that SAP Note 3255746 restricts. The June 9 security patch blocks unauthorized ODP-RFC calls only — our extraction makes none, so a Gold DB refresh runs unchanged after the patch. No action and no patch deferral are required on our account.

⛔ What the note restricts (ODP-RFC) — we do NOT use
  • RODPS_REPL_* — ODP replication RFC interface
  • ODQ_* — Operational Delta Queue
  • /SAPDS/ operators — SLT / Data Services
  • CDS-view / extractor / DataSource subscriptions
  • Change-data-capture & delta replication to 3rd-party tools
✔ What the Gold DB uses (out of scope)
  • RFC_READ_TABLE — generic single-table read (fn group SDTX)
  • Paginated ROWCOUNT/ROWSKIPS, WHERE via OPTIONS
  • Transparent application tables (BKPF, BSEG, FMIFIIT…)
  • pyrfc over SNC/SSO, P01 read-only
  • No delta queue, no subscription, no ODP context
Why this holds: ODP and RFC_READ_TABLE are different frameworks. ODP is a replication mechanism (delta queues, subscriptions, change-data-capture). RFC_READ_TABLE is the equivalent of "SELECT these fields FROM this table WHERE…, return the rows" — no delta, no subscription. SAP Note 3255746, its self-assessment (Note 3439624) and the June 9 patch all target ODP only.
Code evidence: rfc_helpers.py:147 · extract_bkpf_bseg_parallel.py:94 · repo-wide scan for ODP APIs = 0 calls Independently corroborated: Theobald, Databricks, Microsoft, Qlik & CData all scope the note to RODPS_REPL_* (ODP-RFC) only; table-read RFC is named a compliant alternative. For SAP sign-off: run the Note 3439624 self-assessment on P01 + D01 to convert this into SAP's own confirmation.
Assessed 2026-06-02 against the extraction pipeline source of truth + independent public sources. RFC_READ_TABLE is currently the vendor-recommended compliant alternative to ODP-RFC. Strategic watch item only: SAP's broader direction to gatekeep third-party data access (Forrester 2026) — not an imminent restriction. Brain: claims #203 (TIER_1) / #204, rule feedback_classify_exact_api_before_compliance_call.
