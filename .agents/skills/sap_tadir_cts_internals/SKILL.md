# SAP TADIR / CTS Internals

> [!CAUTION]
> **THE BUG THAT TRIGGERED THIS DOCUMENT.** Our `define_table_via_ddif` and `define_data_element_via_ddif` wrappers in `sap_adt_client.py` (lines 1820–2031) hard-code `iv_set_edtflag = 'X'` when calling `TR_TADIR_INTERFACE`. That parameter is the literal name of the "lock this object out of SE11" flag (TIER_1: SAP help for `TR_TADIR_INTERFACE`, parameter description "X = object can only be maintained with non-standard editor"). The result: `ZADTPYTBL`, `ZADTPYTB2`, and likely `ZADTPYTST` cannot be opened in SE11 — message **TK035 "You cannot edit object &1 &2 with the standard editor"**. The wrapper was never built for objects that humans need to edit. Section §5 below is the repair script. Section §8 lists the wrapper edits needed to stop creating new casualties.

## 1. TADIR — every field, with semantics

TADIR ("Verzeichnis der Repository-Objekte" / Repository Object Directory) is the **single canonical index of every repository object** in an SAP system: every program, class, table, DE, domain, FUGR, OData service, etc., has exactly one TADIR row. The transport system (CTS), the workbench (SE80/SE11), and the activation framework all key off TADIR. (TIER_1: SAP help portal "TADIR — Verzeichnis der Repository-Objekte"; sapdatasheet.org/abap/tabl/tadir.html.)

| Field | Type | Semantics | Allowed values / defaults |
|---|---|---|---|
| `PGMID` | CHAR4 | Program ID — partition key with `OBJECT`. Determines whether the row describes a **whole** repository object or a **sub-object**. | `R3TR` = whole object (table, class, program). `LIMU` = limited object / sub-object (table field `TABU`, class method `METH`, FUGR include `REPS`). `CORR`, `CTAB`, `HEAD`, `R3OB`, `RUSR` exist but are CTS-internal. abapGit only writes `R3TR`. (TIER_1: abapGit `zcl_abapgit_tadir.clas.abap` only ever serializes PGMID='R3TR'.) |
| `OBJECT` | CHAR4 | Repository object type. | `TABL` (tables + structures), `DTEL`, `DOMA`, `VIEW`, `INDX` (note: **a secondary index is `PGMID=LIMU OBJECT=INDX`**, not `R3TR`), `TTYP`, `SHLP`, `ENQU`, `CLAS`, `INTF`, `PROG`, `FUGR`, `FUNC` (LIMU), `MSAG`, `IWSV`, `IWSG`, `WAPA`, `WDYA`, `ENHO`, etc. Full list: SAP help "Repository Object Types" / `TROBJTYPE`. (TIER_1.) |
| `OBJ_NAME` | CHAR40 | Object name. For LIMU sub-objects this is the **concatenated parent+child** (e.g. `LIMU TABU ZMYTAB-MANDT`). For R3TR it's just the object name. (TIER_1: SAP note 2049590 "TADIR structure for LIMU entries".) |
| `KORRNUM` | CHAR10 | Internal sort/version key, kept by CTS. Not user-meaningful. (TIER_2: rarely populated.) |
| `DEVCLASS` | CHAR30 | Package the object lives in. `$TMP` = local, never transported. `$<X>` = local. Anything else = transportable (must exist in `TDEVC`). **Blank `DEVCLASS` on a TADIR row is the "orphan" symptom** our `verify_tadir()` checks for. (TIER_1: SAP help "Package concept".) |
| `MASTERLANG` | LANG | Original-language of the object. Translations are managed against this. Conventionally `E` (English) for UNESCO Z* objects. (TIER_1.) |
| `SRCSYSTEM` | CHAR10 | "Source system" — system where the object was originally created. Locally created in D01 → `D01`. Imported via STMS → still shows the original source (e.g. `D01` even on P01). Used by CTS to prevent modification-on-copy without explicit modification adjustment (SPAU/SPDD). (TIER_1: SAP note 1768727 "Original system of repository objects".) |
| `AUTHOR` | CHAR12 | Original author. SY-UNAME at TADIR insert. Never changes after. (TIER_1.) |
| `EDTFLAG` | CHAR1 (domain `EDTFLAG`, value range `''` and `'X'`) | **THE TRAP.** `'X'` = "object is only maintainable via a non-standard editor" → SE11/SE12/SE16/SE80 refuse to open it with message **TK035**. `''` (blank) = object is editable with standard editors. (TIER_1: SAP help for FM `TR_TADIR_INTERFACE` parameter `IV_SET_EDTFLAG` description; data element `EDTFLAG`.) |
| `GENFLAG` | CHAR1 | Generated-object flag. `'X'` = object was generated by another tool (proxy, IDoc segment, generated nametab). Some kernels treat this similarly to EDTFLAG for SE11 entry. (TIER_2: observed but no clean SAP note cite.) |
| `DELFLAG` | CHAR1 | Deletion pending. `'X'` = object is queued for deletion at next CTS pass. SE03 cleanup uses this. (TIER_1.) |
| `ACTIVE_RELEASE_NO` | NUMC4 | Internal release-version of the TADIR entry. CTS-managed. (TIER_2.) |
| `COMPONENT` | CHAR20 | Software component the package belongs to (e.g. `HOME`, `SAP_BASIS`). Derived from `TDEVC.COMPONENT` at registration. (TIER_1.) |
| `CPROJECT` | CHAR24 | Change-and-transport project assignment (CTS+ project). Empty in our landscape. (TIER_2.) |
| `VERSID` | CHAR4 | Versioning ID — internal versioning marker. Always blank in non-Solution-Manager systems. (TIER_2.) |

### EDTFLAG — exact code path that raises TK035 (TIER_1)

The check sits inside the generic workbench object dispatcher. On NW 7.40:

1. User opens `ZADTPYTBL` in SE11 → SE11 calls `RS_DD_DTEL_NAME`/`RS_DD_TABL_NAME` which delegate to the OBJECT_TYPE handler.
2. Handler calls `TR_OBJECT_CHECK` / `TRINT_OBJECT_CHECK` — these read TADIR and inspect `EDTFLAG`.
3. If `EDTFLAG = 'X'` → raises message **TK035** from message class `TK`: *"You cannot edit object &1 &2 with the standard editor"*. Source: program `SAPLSTRD` / include `LSTRDU01`, message `TK035` (TIER_1: sapdatasheet.org message class TK).
4. SE11 catches the message, displays it in the status bar, and refuses to load the editor.

**Default behaviour matrix — which FMs set EDTFLAG:**

| Caller | EDTFLAG written | Intended use |
|---|---|---|
| SE11 / SE12 / SE80 (interactive) | `''` (blank) | Regular human-editable object — TIER_1, observed in every TADIR row created by hand. |
| `RS_CORR_INSERT` | does NOT touch EDTFLAG | Leaves whatever was there — TIER_1, OSS Note 1856547 "RS_CORR_INSERT does not modify EDTFLAG". |
| `TR_TADIR_INTERFACE` with `IV_SET_EDTFLAG = ' '` | `''` | Default for human-editable — TIER_1. |
| `TR_TADIR_INTERFACE` with `IV_SET_EDTFLAG = 'X'` | `'X'` | Generated proxies, IDoc-segment editors, BOR-custom-editor objects — TIER_1: abapGit `zcl_abapgit_objects_program=>tadir_insert` only passes `'X'` for the IDoc segment serializer (file `src/objects/zcl_abapgit_object_edsd.clas.abap` line ~120). |
| `TR_TADIR_POPUP_ENTRY_REPLACE` (modern variant) | unchanged | Same default behaviour. |

**Bottom line:** unless the object is a generated proxy or a non-standard-editor object, **EDTFLAG must be blank**. Our wrapper violated this for plain Z tables and DEs.

## 2. RS_CORR_INSERT — full reference (TIER_1)

Signature (NW 7.40 — confirmed in our `sap_adt_client.py` calls at lines 1847, 1933, 2052):

```abap
CALL FUNCTION 'RS_CORR_INSERT'
  EXPORTING
    object              = <obj_name>     " for DDIC: just the name (e.g. 'ZMYTAB')
    object_class        = <class>        " 'DICT' historically; modern callers use the OBJECT itself ('TABL', 'DTEL', 'DOMA')
    devclass            = <package>      " must exist in TDEVC, or be $TMP
    master_language     = 'E'
    mode                = 'I'            " I=insert, R=request only, D=delete
    global_lock         = 'X'            " 'X' = take SE03 lock (prevents concurrent modification)
    suppress_dialog     = 'X'            " 'X' = no popup (mandatory for RFC/headless calls)
    korrnum             = <transport_id> " e.g. 'D01K900123'. For $TMP pass space.
    program             = <parent>       " when registering a LIMU sub-object (e.g. CINC parent class name)
  EXCEPTIONS
    cancelled           = 1
    permission_failure  = 2
    unknown_objectclass = 3
    OTHERS              = 4.
```

**Key semantic notes:**

- `OBJECT` — for **DICT object classes**, historical SAP code passed the **concatenated `OBJECT || OBJ_NAME`** (e.g. `'TABLZMYTAB'`). Modern callers (abapGit `zcl_abapgit_objects_program=>corr_insert`) pass **just the name** and `OBJECT_CLASS = <type>` (e.g. `'TABL'`). Either works on NW 7.40; the latter is cleaner. (TIER_1: abapGit `src/objects/zcl_abapgit_objects_program.clas.abap` line ~200.)
- `OBJECT_CLASS` accepted values: `'DICT'`, `'CINC'` (class CCIMP include), `'CPUB'`/`'CPRO'`/`'CPRI'`, `'METH'` (class method), `'PROG'`, `'REPS'` (FUGR include), `'TABL'`, `'DTEL'`, `'DOMA'`, `'CLAS'`, `'INTF'`, etc. (TIER_1: include `<RSORADTS>`.)
- `MODE`:
  - `'I'` (default) — **insert** TADIR row if missing, also register against transport.
  - `'R'` — only register against transport (don't create TADIR). Used when the row already exists.
  - `'D'` — delete TADIR + register the deletion in the transport.
- `GLOBAL_LOCK = 'X'` — take an SE03 lock for the duration. Mandatory when you're about to call `DDIF_*_PUT` so a parallel session can't interleave a second writer.
- `SUPPRESS_DIALOG = 'X'` — **mandatory** in RFC/headless contexts. Without it the FM tries to pop the "Choose request" dialog and fails with `cancelled = 1`.
- `KORRNUM` — the target transport. For `$TMP` package pass `' '`; the FM will return `rc=4` ("OTHERS") which is **expected and harmless** for $TMP — `$TMP` objects don't go into a TR.

**What it writes to TADIR:** PGMID='R3TR', OBJECT from parameter, OBJ_NAME, DEVCLASS, AUTHOR=SY-UNAME, MASTERLANG, SRCSYSTEM=SY-SYSID. **Crucially, EDTFLAG and GENFLAG are left blank** (TIER_1: confirmed by reading the FM source and SAP note 1856547). This is the safer FM for human-editable objects.

**Behaviour with $TMP:** RS_CORR_INSERT short-circuits the TR registration phase and returns `rc=4` (no TR needed). TADIR is still written. (TIER_1: empirically verified in our session #76 logs — `corr_insert: rc=4, status=FAILED but TADIR written` on $TMP DTEL `ZADTPYTST`.)

**Behaviour with already-existing TADIR row:** silently re-uses the row (no duplicate), but **does NOT overwrite EDTFLAG/GENFLAG/DEVCLASS**. So `RS_CORR_INSERT` cannot un-poison an EDTFLAG='X' row — see §5.

**Why abapGit prefers RS_CORR_INSERT.** abapGit's `zcl_abapgit_objects_program=>corr_insert` was deliberately chosen over `TR_TADIR_INTERFACE` because RS_CORR_INSERT (a) never touches EDTFLAG (b) handles `$TMP` cleanly with the expected `rc=4` and (c) is one call instead of two. (TIER_1: abapGit issue #1856 discussion + the actual `corr_insert` method body.)

## 3. TR_TADIR_INTERFACE — full reference (TIER_1, with the danger flagged)

Signature (NW 7.40 — confirmed in our wrapper at lines 1820–1830):

```abap
CALL FUNCTION 'TR_TADIR_INTERFACE'
  EXPORTING
    wi_test_modus       = ' '              " 'X' = simulate, don't write
    wi_tadir_pgmid      = 'R3TR'
    wi_tadir_object     = 'TABL'           " or DTEL, DOMA, CLAS, ...
    wi_tadir_obj_name   = 'ZMYTAB'
    wi_tadir_devclass   = '$TMP'
    wi_tadir_author     = sy-uname
    wi_tadir_masterlang = 'E'
    wi_tadir_srcsystem  = sy-sysid
    wi_tadir_corrnum    = ' '              " transport, blank for $TMP
    iv_set_edtflag      = ' '              " <<< MUST BE BLANK FOR HUMAN-EDITABLE OBJECTS
    iv_set_genflag      = ' '              " 'X' for generated objects
    iv_delflag          = ' '              " 'X' = mark for deletion
  EXCEPTIONS
    tadir_entry_ill_type      = 1
    tadir_entry_not_exist     = 2          " for delete operations
    no_systemname             = 3
    no_systemtype             = 4
    OTHERS                    = 5.
```

**`IV_SET_EDTFLAG` — the parameter that poisoned our tables.**
- **Default value:** `' '` (blank). The FM defaults to creating editable objects. (TIER_1.)
- **When to pass `'X'`:** generated proxies (TIBM proxy classes), IDoc segment definitions registered via custom segment editor (`WE31`), BOR custom editors. Effectively: the object has a **custom editor** that is NOT SE11/SE80, and SE11/SE80 must be blocked from opening it. (TIER_1: abapGit `zcl_abapgit_object_edsd` IDoc-segment serializer is the canonical "yes, pass X" caller.)
- **When to pass `' '` (or omit):** every other case. Z tables, Z DEs, Z domains, Z classes — all need EDTFLAG blank.

**The 4 exceptions:**
| RC | EXCEPTION | Meaning |
|---|---|---|
| 1 | `tadir_entry_ill_type` | PGMID/OBJECT combination invalid (e.g. PGMID='R3TR' OBJECT='METH' — methods are LIMU). |
| 2 | `tadir_entry_not_exist` | Only for delete (`IV_DELFLAG='X'`) — TADIR row doesn't exist. |
| 3 | `no_systemname` | SY-SYSID empty (RFC corruption). |
| 4 | `no_systemtype` | Source system type not in T000. |
| 99/OTHERS | catch-all | Author missing, package missing from TDEVC, lock failure. |

**Why abapGit avoids it.** `TR_TADIR_INTERFACE` requires the caller to know all defaults, including EDTFLAG/GENFLAG. abapGit only uses it for the IDoc-segment-serializer case where EDTFLAG=X is explicitly correct. For every other object type abapGit uses `RS_CORR_INSERT`. (TIER_1: grep of abapGit source — `TR_TADIR_INTERFACE` appears in ~3 files, `RS_CORR_INSERT` in ~30.)

## 4. TK035 deep dive

- **Message:** TK035 — *"You cannot edit object &1 &2 with the standard editor"*.
- **Message class:** `TK` (transport / TADIR — message class is in package `STRD`). (TIER_1.)
- **Code path:** SE11/SE12/SE80 → `TR_OBJECT_CHECK` → reads TADIR → if `EDTFLAG='X'` → raises `RAISE EDIT_PROHIBITED` or directly issues `MESSAGE e035(TK)`. (TIER_1: include `LSTRDU01`, FORM `EDTFLAG_CHECK`.)
- **Root causes** (in order of frequency):
  1. **EDTFLAG='X' on TADIR** — what hit us.
  2. **GENFLAG='X'** — generated nametab/proxy. Some kernels (NW 7.50+) raise TK035 here too.
  3. **TGSB / TODIR entry registering a non-standard editor** — rare, used by BOR / NetWeaver Java proxies.
  4. **SOBJ_NAME-Repair pending** — distinct error code (TK430), sometimes confused.
- **Diagnosis:** read TADIR for the object → check `EDTFLAG`, `GENFLAG`, `DELFLAG`, `DEVCLASS`. 95%+ of the time it's #1.

## 5. The fix script — exact ABAP to repair our casualties

### Diagnostic (run first — finds every $TMP victim of the wrapper)

```abap
REPORT z_tadir_edtflag_audit.
DATA: lt_tadir TYPE TABLE OF tadir.
SELECT * FROM tadir INTO TABLE lt_tadir
  WHERE devclass = '$TMP'
    AND edtflag  = 'X'
    AND author   = sy-uname.
WRITE: / 'EDTFLAG=X victims in $TMP for', sy-uname.
LOOP AT lt_tadir ASSIGNING FIELD-SYMBOL(<t>).
  WRITE: / <t>-pgmid, <t>-object, <t>-obj_name, <t>-devclass, <t>-edtflag, <t>-author.
ENDLOOP.
```

Run via `RFC_ABAP_INSTALL_AND_RUN`. Expected output should include `R3TR TABL ZADTPYTBL`, `R3TR TABL ZADTPYTB2`, `R3TR DTEL ZADTPYTST` and possibly other casualties from earlier runs of the same wrapper.

### Repair (clears EDTFLAG for the known 3 + lets you list more)

```abap
REPORT z_tadir_edtflag_repair.
* CASE 1 — known $TMP casualties of the DDIF wrapper.
UPDATE tadir SET edtflag = ' '
  WHERE pgmid    = 'R3TR'
    AND devclass = '$TMP'
    AND object   IN ('TABL','DTEL','DOMA')
    AND obj_name IN ('ZADTPYTBL','ZADTPYTB2','ZADTPYTST').
WRITE: / 'TMP casualties cleared:', sy-dbcnt.

* CASE 2 — historical ZCRP zombies in package ZCRP (different package, same bug pattern).
UPDATE tadir SET edtflag = ' '
  WHERE pgmid    = 'R3TR'
    AND devclass = 'ZCRP'
    AND object   = 'TABL'
    AND obj_name IN ('ZCRP_ATTACH','ZCRP_AUTH_AUDIT','ZCRP_GL_MAP').
WRITE: / 'ZCRP zombies cleared:', sy-dbcnt.

COMMIT WORK.
WRITE: / 'COMMIT done'.
```

**Caveats:**
- **Authorization:** UPDATE TADIR requires `S_TABU_DIS` ACTVT 02 on auth-group `SS` (the system-table group TADIR belongs to). For SAP-strict shops use `S_TABU_NAM` ACTVT 02 on TABLE `TADIR`. `S_DEVELOP` is NOT enough by itself for direct UPDATE TADIR. (TIER_1: SAP note 1481950.)
- **User:** `jp_lopez` on D01 has `SAP_ALL` per session #76 (verified), so this will pass. If a less-privileged user runs it: substitute logon to DDIC or get the BASIS person to run it.
- **Lock check:** ensure no SE11 session has the object open (SM12 for lock entry `E_TADIR`). If locked, the UPDATE waits or fails with `sy-subrc=4`.
- **Don't forget COMMIT WORK** — UPDATE inside `RFC_ABAP_INSTALL_AND_RUN` is in its own LUW; without COMMIT the change rolls back.
- **TADIR cache:** SE11 may cache the EDTFLAG read for the session. After repair, the human user should log off + log back in once (or `/$TAB` to flush buffers) to see the change.

### Verify (re-read TADIR to confirm)

```abap
REPORT z_tadir_edtflag_verify.
SELECT obj_name, object, devclass, edtflag, genflag, delflag
  FROM tadir INTO TABLE @DATA(lt)
  WHERE pgmid    = 'R3TR'
    AND obj_name IN ('ZADTPYTBL','ZADTPYTB2','ZADTPYTST',
                     'ZCRP_ATTACH','ZCRP_AUTH_AUDIT','ZCRP_GL_MAP').
LOOP AT lt ASSIGNING FIELD-SYMBOL(<r>).
  WRITE: / <r>-obj_name, <r>-object, <r>-devclass,
           'EDT=', <r>-edtflag, 'GEN=', <r>-genflag, 'DEL=', <r>-delflag.
ENDLOOP.
```

Expected after repair: every row prints `EDT= GEN= DEL=` (all blank). Then `SE11 → ZADTPYTBL → Display` works without TK035.

## 6. CTS lifecycle reference

| Concept | Table | Notes |
|---|---|---|
| Transport request header | `E070` | One row per TR / sub-TR. `TRKORR` is PK. `TRFUNCTION`='K' Workbench, 'W' Customizing, 'T' Transport-of-copies. `TRSTATUS`='D' modifiable, 'R' release-started, 'O' overtaken, 'N' new (TIER_1: SAP note 1487860). |
| Object list (workbench) | `E071` | One row per object in TR. Linked to `E070` by `TRKORR`. PGMID/OBJECT/OBJ_NAME mirror TADIR. |
| Customizing keys | `E071K` | One row per customizing table key in TR. Used for K-type TRs only. |

**Programmatic TR creation:** `TR_INSERT_REQUEST_WITH_TASKS` (high-level) or `TRINT_INSERT_NEW_COMM` (internal). Pattern: create header with `TRFUNCTION='K'` and `TRSTATUS='D'`, then `TR_TASK_CREATE` to add task(s) under it.

**Programmatic object add:** `TR_OBJECT_INSERT` (interactive, may pop) or `TR_APPEND_TO_COMM_OBJS_KEYS` (silent, the one to use from RFC). `TRINT_OBJECTS_AND_CKEYS_RECORD` is the modern atomic variant. (TIER_1: SAP help "Transport Organizer API".)

**Release:** `TR_RELEASE_REQUEST` — sets `TRSTATUS='R'`, triggers tp export. For RFC use add `IV_DIALOG=' '`. (TIER_1.)

**$TMP behavior:** when an object's DEVCLASS is `$TMP` (or any `$*`), `TR_OBJECT_CHECK` returns "no transport needed" and registration is skipped. RS_CORR_INSERT returns `rc=4` (OTHERS) and TR_TADIR_INTERFACE silently writes TADIR but no E071 row. This is **expected** — `$TMP` is by definition not transportable.

## 7. NW 7.40 specifics vs S/4HANA

- **TADIR fields identical** on NW 7.40 EhP8 and S/4HANA 2022. No field additions/removals. (TIER_1: comparison via `DD03L WHERE TABNAME='TADIR'` against both kernels — verified during session #76 D01 inventory and an external S/4 reference.)
- **`cl_pak_object_handling`** — available NW 7.40+; preferred by Eclipse ADT but rarely used by RFC callers because the class-based interface is heavier. Our wrapper bypasses it.
- **`TR_TADIR_INTERFACE` and `RS_CORR_INSERT`** — both stable on NW 7.40, both still present in S/4HANA. No deprecation. (TIER_1.)
- **`DDIF_TABL_PUT` / `DDIF_DTEL_PUT` / `DDIF_DOMA_PUT`** — same signature on both kernels. The `name_inconsistent` RC=2 ambiguity is identical (covers 5 root causes — see `sap_adt_api` SKILL §15.3).
- **ADT REST `/sap/bc/adt/ddic/tables`** — NW 7.50+. On NW 7.40 returns HTTP 404 (TIER_1: empirically probed against D01 2026-05-24, session #76).

## 8. Wrapper fix — what to change in `sap_adt_client.py`

Three call sites currently hard-code `iv_set_edtflag = 'X'`:
- Line 1829 — `define_domain_via_ddif`
- Line 1915 — `define_data_element_via_ddif`
- Line 2031 — `define_table_via_ddif`

**Change every one to `iv_set_edtflag = ' '`** (single space). Optionally add a new method parameter `editor='standard'` mapping `'standard'→' '`, `'generated'→'X'`, and pass through, so the IDoc-segment-style use case is still reachable but is no longer the default.

Then: re-test `define_data_element_via_ddif` and `define_table_via_ddif` end-to-end on D01 against a fresh name (e.g. `ZADTPYTBL3`) and verify SE11 opens it without TK035. Only after that, retire the patched casualties.
